# ADR 0003：モックから実アプリへの移行

- 決定日：2026-11-10
- 着手根拠：POのチャット「mainを最新化」「今のモック画面の通りにフロントエンド、バックエンドを実装」「バックエンドはhono」「完了後はPR」。モックの画面・操作範囲を実装対象とする。
- 認証の承認：POが「Tailscale Serveが付与する利用者情報をローカル専用バックエンドで受け取り、設定した2人だけ許可する方式」「PC内の他プロセスも信頼」「公開・本番反映なし」に「その方式で進める」と回答。
- マージ・本番反映は未承認、未実施。

## 実装

React/Viteの共通Appを維持し、バックエンドはHono/Node.js 24。PostgreSQL 17.9のDockerをループバックで使用し、写真の元バイト列とメタデータを除去したJPEGを非公開ディレクトリへ保存する。pgのパラメーター化SQL、sharpの画像検証・変換、exifrのEXIF抽出を使用。写真のバイト列をDB登録より先に書き込み・flushし、成功応答はDB登録後に返す。DB応答喪失時のコミット有無が不明なため、失敗時に元ファイルを削除しない。孤立ファイルは非公開で保持する。ディスク容量の監視と手動照合が必要。バックアップ・物理消去の自動化は今回追加しない。

写真・お気に入り・ゴミ箱状態・所属アルバム・空アルバムはDBへ保存。モック同様、ゴミ箱内の写真を許可利用者が閲覧・ダウンロード・復元できる。保持期限と完全削除は追加しない。JPEG/PNG/WebP、1枚10MiB、静止画像・40メガピクセル以下を画像デコーダーで検証する。検索は取得済みの名前・アルバムをブラウザー内で絞り込む。初期版は全件取得で、大規模ライブラリ向けのページングは今後の課題。

## 認証境界

Honoは必ず127.0.0.1で待ち受ける。Tailscale Serveを唯一のネットワーク入口として、`Tailscale-User-Login`を設定した2人のログイン名と完全一致で照合する。Tailscale Serveは受信した利用者ヘッダーを消去し、WhoIsで特定した利用者の値を付与する。タグ付き端末には利用者情報を付与しない。

公式実装確認：<https://github.com/tailscale/tailscale/blob/main/ipn/ipnlocal/serve.go> の `addTailscaleIdentityHeaders`。Funnel識別ヘッダーがある場合も拒否する。ローカルPCのプロセスはヘッダーを偽装できるため、この構成はPC上のプロセスを信頼する。ポートを0.0.0.0へ変更したり、公開プロキシへ接続したりしない。

更新はAPP_ORIGINとOriginの完全一致、およびX-Photo-Request: 1を要求する。CORS許可を追加しない。写真・API・静的配信にも認証とprivate, no-storeを適用する。秘密値・SQL・内部パスをエラーに含めない。利用者の登録APIはない。

`DEV_USER`はループバックオリジン限定のローカル検証用。Tailscale稼働では必ず解除する。環境変数の設定変更にはプロセス再起動が必要。

## 契約と旧案の整理

`api/openapi.yaml`を実装のHTTP契約とし、未実装だったv1レビュー案と試作専用の二重契約を統合する。試作APIのパス・Photoの表示形を維持し、multipartアップロード、元画像・サムネイル、利用者・アルバムを追加する。型・クライアント・MSWルートを固定ツールで生成する。旧v1案は提供済みAPIではなく、互換性を保証する既存クライアントはない。

DBは`apps/backend/src/schema.sql`と対応する`db/schema.dbml`へ具体化する。旧DBMLは未適用のレビュー案であり、既存DBの移行・データ削除は行わない。EXIFの保持内容は製品仕様に従い、日時・GPSを一覧APIに返さず、地名解決を行わない。画面のサンプル撮影日・場所は実データに見せず追加日（UTC）と未表示の注記へ変更する。
