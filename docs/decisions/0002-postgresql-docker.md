# ADR 0002：PostgreSQLをPC内のDockerで稼働

- 状態：方針承認済み、未実装
- 決定日：2026-11-10
- 承認者：PO
- 承認元：チャット「postgresql確定でいいよ。PC内のDockerでDBコンテナを立てる想定」

## 決定

DBにPostgreSQLを採用し、利用者のPC内のDockerコンテナで稼働させる。スキーマの正は `db/schema.dbml` とし、PostgreSQLの型・Enum・制約で設計する。

この承認はDB製品とDBの稼働方式を対象とする。テーブル・制約の設計案全体、バージョン、Compose設定、アプリ配置、写真保存先、マージ、本番リリースは別途確定する。ADR 0001の構成案全体を承認済みとはしない。

## 理由と影響

現在のDBMLの型と制約をそのまま具体化でき、将来の撮影日時や位置による検索にも拡張できる。PC停止・スリープ・Docker停止中はDBを利用できない。単一PCのため、ディスク故障に備えた別保存先のバックアップが必要になる。

## 構築時に具体化する事項

以下は実装前に具体化する設計項目であり、このADRによる構築済み設定ではない。

- サポート対象のPostgreSQLメジャー・パッチと公式Dockerイメージの固定方法。latestだけを指定しない。
- DBデータの永続化先（Docker volumeまたはbind mount）と容量管理。コンテナ再作成で失わない構成にする。
- アプリからの接続経路。DBをインターネットへ公開せず、同一Dockerネットワーク等を検討する。PC上の管理ツール接続が必要ならループバックへの限定公開を検討する。
- 初期化・マイグレーション用とアプリ用の権限、資格情報の保管、ヘルスチェック、起動・終了手順。
- PostgreSQLに対応したバックアップ方法と写真との整合性、保持期間・保存先・復元検証。稼働中のデータディレクトリの単純コピーをバックアップ手順としない。
- メジャーバージョン更新時の移行・ロールバック手順。イメージタグの置換だけで更新しない。

## 実施状況

今回の変更はDBMLと文書への決定の記録のみ。利用者のPCへの接続、コンテナ起動、DB作成、データ移行、本番変更は行っていない。
