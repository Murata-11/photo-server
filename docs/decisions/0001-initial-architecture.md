# ADR 0001：初期構成案

- 状態：提案中
- 提案日：2026-11-10
- PO承認：未取得

## 背景

2人限定の写真共有アプリを、AIによる開発とPOの承認で継続運用する。Tailscaleの利用と2人の同等権限は確認済み。保存容量、予算、設置機器、許容停止時間は未決。

## 提案

単一サーバー上でDocker Composeを使い、Tailscale Serveを入口としてアプリ内でも2人のIDを確認する。写真とDBは永続化し、暗号化したバックアップを別の保存先に保持する。

配置先は自宅PC・NASまたはVPSから、容量、費用、回線と停止許容度に基づいてPOが選ぶ。DB製品とDB配置の方針は後続の[ADR 0002](0002-postgresql-docker.md)で確定した。アプリの配置先、言語などは別途提案する。

## 代替案

| 案 | 利点 | 課題 |
| --- | --- | --- |
| 自宅PC・NAS | 大容量の写真を保存しやすい | 停電、回線、機器故障への対応が必要 |
| VPSと外部ストレージ | 自宅環境に依存しない | 継続費用と転送・保存容量の管理が必要 |
| 複数台・Kubernetes | 冗長化や拡張に対応しやすい | 初期の2人用アプリには管理負担が大きい |

## 影響

単一サーバー構成では、そのサーバーの停止中は利用できない。バックアップは可用性を代替しない。コンテナや稼働プロセスだけに写真・DBを保持しない。復元先と鍵の保管方法が必要になる。

## 承認前に決めること

- 配置先と予算、容量見込み
- 主要技術とサポート対象バージョン
- 利用者IDとTailnetの管理方法
- 許容データ損失（RPO）と復旧時間（RTO）
