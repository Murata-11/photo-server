## 実装と検証環境

PUT `/api/photos/trash` / `trashPhotos` を実装。1〜100枚のIDを検証・正規化し、ID順に対象写真をロックして全件存在確認後、同一トランザクションで `deleted=true` にする。既移動は成功とし、元画像・表示画像・メタデータ・所属・お気に入りを変更しない。DB構造・依存関係・認証変更はない。右上のアイコンと確認画面は承認済みUIを使用する。

ローカルDockerのPostgreSQL 17.9（`issue23-test-db`コンテナ、ループバック54323番）に、破棄可能な専用DB `issue26_test` と `issue26_e2e` を作成。E2Eの写真保存先も専用ディレクトリを使用し、本番データを使わない。Node.js 24・pnpm 10.34.9・Chromiumで検証する。PC 1440×1000・393×852、Storybookは320px幅も対象。

実DBでは入力境界・不存在混在・途中失敗の全件ロールバック・再送・元画像と表示画像の一致・メタデータ等の保持・競合と接続再作成後の保持を確認する。実API E2Eは確認とキャンセル・応答喪失後の同じIDの再送・アルバム枚数／表紙・単一復元・再取得だけの再試行を確認する。
