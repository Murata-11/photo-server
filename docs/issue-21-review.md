## レビュー方法

`pnpm storybook` で起動し、`http://127.0.0.1:6006` の「Issue 21 / 複数アルバム」を開く。各Storyで詳細ツールバーの「アルバムに追加・解除」アイコンを押す。PC（1280×852）とスマートフォン（393×852）の両方で確認する。

| Story          | 確認操作                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Multiple       | アイコン→チェックの2操作で追加・解除。保存ボタンなし、再度開いても所属が維持されることを確認                            |
| Saving         | チェック変更した行の保存中表示・無効化と、他行が操作できること、保存中でも閉じられることを確認                          |
| Error          | 失敗行だけチェックを戻し、行内エラーと再試行を確認                                                                      |
| PartialFailure | 既存所属の解除と空アルバムへの追加を行い、成功行を維持し失敗行だけ戻すことを確認                                        |
| NoAlbums       | アルバム0件の案内と内容に応じたコンパクトな高さを確認                                                                   |
| Trash          | ゴミ箱内でも所属を即時編集できることを確認                                                                              |
| ManyAlbums     | 121件と長い名前。所属中フィルター、固定した並び、一覧のみスクロール、PCの位置・高さ制限とスマートフォン下部パネルを確認 |

Tab/Spaceで操作し、外側クリック・Escape・閉じるで破棄確認なしに終了することを確認する。写真情報は要約表示のみ。各行の状態を保持し、保存中・失敗した行は所属中フィルターでも残す。開始済みの保存処理は閉じても継続し、閉じた後の失敗は通知する。チェック状態を早く表示するが、保存中表示が消えるまで保存完了とは扱わない。

HTTP契約は `pnpm build:review` のSwagger UIを参照する。個別追加・解除を維持し、全所属の置き換えは行わない。アルバム自体の管理画面は別Issueとする。

## 変更の境界と次の手順

共有Appを更新するため通常起動のUIも新契約になるが、バックエンドは旧契約のまま。本仕様PRを単独でデプロイしない。後続実装PRで実API・履歴付き移行・DBML・DDL・実APIテストを更新する。現行バックエンドテストが旧契約を確認することは仕様PRで意図した状態であり、新APIへの適合を保証しない。

本PRの対象コミットに対するPOの仕様承認と、別途マージ承認を記録する。仕様PRのmainへのマージ後に `docs/workflow.md` のready条件を再判定し、POがreadyを付与する。仕様PRではIssue #21を閉じない。

### 検索削除・スマートフォン表示修正（2026-11-11）

POの「検索がいらない。スマホ画面で表示が壊れる。」に基づき検索欄を削除。852×393の横向きではPC用のアンカー位置と検索を含むヘッダーのため一覧の表示高が約31pxになることを再現した。高さ500px以下でも下部パネルを使い、最大高さを画面高−12pxへ変更。説明文はスクリーンリーダー向けに残して見出しを簡潔にし、閉じる操作は44×44pxを確保する。小幅画面の復元操作はアイコンとアクセシブルな操作名を維持して文字のはみ出しを防ぐ。

タッチ操作の回帰確認対象は320×568、375×667、393×852、852×393。通常の多数アルバムとゴミ箱の両方で、横はみ出し、一覧の高さ、最後の項目までのスクロールとタップ、閉じる操作を確認する。実機Safariの検証結果とは区別する。

末尾の行へ移動するとパネル全体がスクロールし見出しが隠れる問題もスクリーンショットで検出。スクロール領域をfieldsetから独立したgroup要素へ変更し、パネル本体はoverflow: clipとした。末尾操作後も見出しがパネル内に残り、本体のscrollTopが0であることを回帰テストに追加。

検証結果：画面操作16件成功後、上記スクロール修正に関係するタッチ端末4サイズのテストを再実行して全件成功。Vitest 12件、Lint、型検査、Storybook型検査・ビルド、OpenAPI検証・レビューサイト生成、レビュー配信3件成功。320px幅と横向きの修正後スクリーンショットを目視確認。実機Safariは未確認。
