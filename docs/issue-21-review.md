## レビュー方法

`pnpm storybook` で起動し、`http://127.0.0.1:6006` の「Issue 21 / 複数アルバム」を開く。各Storyで「写真の情報」を押す。PC（1280×852）とスマートフォン（393×852）の両方で確認する。Storybookのフィクスチャのみを使い、DB・本番写真を必要としない。

| Story    | 確認操作                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------- |
| Multiple | 2所属を表示し、片方を外して他方が残ることを確認。空のアルバムへ追加し、全所属解除で未所属になることも確認 |
| Saving   | チェック変更後に保存中表示と全所属入力の無効化を確認                                                      |
| Error    | チェック変更後にエラーと以前のチェック状態の維持、再読み込み案内を確認                                    |
| NoAlbums | アルバム0件と未所属の案内を確認                                                                           |
| Trash    | ゴミ箱内でも所属を追加・解除できることを確認                                                              |

通常の「アプリ / ひより」ではアルバム一覧・名前検索・ゴミ箱/復元を確認できる。Tab/Spaceでチェックを操作し、長い名前でも横にはみ出さないことを確認する。HTTP契約は `pnpm build:review` で生成するSwagger UIから確認する。

## 変更の境界と次の手順

共有Appを更新するため通常起動のUIも新契約になるが、バックエンドは旧契約のまま。本仕様PRを単独でデプロイしない。後続実装PRで実API・履歴付き移行・DBML・DDL・実APIテストを更新する。現行バックエンドテストが旧契約を確認することは仕様PRで意図した状態であり、新APIへの適合を保証しない。
