## レビュー方法

`pnpm storybook` で起動し、`http://127.0.0.1:6006` の「Issue 21 / 複数アルバム」を開く。各Storyで「写真の情報」→「アルバムを編集」を押す。PC（1280×852）とスマートフォン（393×852）の両方で確認する。Storybookのフィクスチャのみを使い、DB・本番写真を必要としない。

| Story          | 確認操作                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Multiple       | 選択変更が保存まで送信されないこと、検索中も選択が残ること、変更件数と保存後の所属を確認                                         |
| Saving         | チェック変更後に「変更を保存」を押し、保存中表示と入力・終了の無効化を確認                                                       |
| Error          | 保存失敗後も選択を維持し、失敗分を再試行できることを確認                                                                         |
| PartialFailure | 空アルバムに追加し既存所属を解除して保存。追加成功と解除失敗を区別し、再試行対象が解除分のみになることを確認                     |
| NoAlbums       | アルバム0件の案内を確認                                                                                                          |
| Trash          | ゴミ箱内でも所属を編集して保存できることを確認                                                                                   |
| ManyAlbums     | 121件のアルバムと長い名前。情報パネルの最大3件＋残り件数、検索・所属中の絞り込み、一覧だけのスクロール、固定検索・保存操作を確認 |

PCは高さ制限付きダイアログ、スマートフォンは全画面。Tab/Spaceで操作し、検索で候補を絞っても選択が残ること、チェック変更で並びが移動しないこと、未保存状態で閉じる・Escape・外側クリックをすると破棄確認になることを確認する。保存中は閉じない。アルバム作成・改名・削除・表紙設定を集約する管理画面は今回の対象外。

HTTP契約は `pnpm build:review` で生成するSwagger UIから確認する。既存の個別追加・解除契約を維持し、全所属の置き換えは行わない。通常の「アプリ / ひより」ではアルバム一覧・検索・ゴミ箱/復元を確認できる。

## 変更の境界と次の手順

共有Appを更新するため通常起動のUIも新契約になるが、バックエンドは旧契約のまま。本仕様PRを単独でデプロイしない。後続実装PRで実API・履歴付き移行・DBML・DDL・実APIテストを更新する。現行バックエンドテストが旧契約を確認することは仕様PRで意図した状態であり、新APIへの適合を保証しない。
