## ネイティブ構成と配布

libvips 8.18.7 / libheif 1.23.7 / libde265 1.0.19を公式ソースのSHA-256検証後にビルド。Debian bookworm、GCC 12.2、CMake 3.25、Meson 1.0、Ninja 1.11、Node.js 24、sharp 0.35.5。HEVCエンコードは無効。ライセンスをイメージに同梱する。

sharpのソースビルド、pnpm deploy後のネイティブバイナリ保持、最終ランタイムイメージでの合成HEICデコードを確認する。通常DockerのOS CAと、クラウドの任意proxy_ca secretの両方を考慮した。フロントエンドはレビュー専用の形式分岐を撤去し、通常起動とStorybookで同じ受付仕様を使う。

## 性能と実行環境の制約

Linux Dockerの実APIでの観測例（合成単色画像、サーバー側JPEG生成・永続化の応答まで）：

| 画像      | 1回目  | 再試行       |
| --------- | ------ | ------------ |
| 48MP HEIC | 1535ms | 1601ms       |
| 60MP HEIC | 1622ms | 1283ms       |
| 48MP JPEG | 292ms  | 別試行も成功 |
| 60MP JPEG | 313ms  | 別試行も成功 |

各要求は新しい子プロセスを使い、sharpのキャッシュは無効。ネイティブビルド等と共有する開発ホストでの観測であり、本番の性能保証ではない。再起動後の一覧・元バイト一致も成功。

プロセスごとのRSSを20ms間隔で合計した観測ピークは580,592KiB（約567MiB）。共有ページの重複と測定用Nodeを含む概算で、cgroupのメモリピークとは異なる。

**1GiB予算の強制下での受け入れ確認はローカルでは未完了。** Dockerに`--memory=1g --cpus=2`を指定したが、daemonは`rootless-mode without cgroups` / CgroupDriver=noneと警告し、コンテナ内memory.maxはホスト全体の8GiBだった。フラグやOOMKilled=falseだけを1GiB下での成功と扱わない。CIのHEICジョブはmemory.maxが1073741824であることを確認してから実API試験を行い、再起動前のピークと終了状態を保存する。CI結果が出るまではこの項目を未実施として残す。
