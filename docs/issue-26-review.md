## レビュー対象

製品ルールはproduct.md第14節、画面はBulkTrash.stories.tsx「Issue 26 / 写真の一括ゴミ箱移動」、APIはOpenAPI `trashPhotos`（PUT `/api/photos/trash`）。1〜100枚・全件トランザクション・既移動を成功とする冪等性を提案する。全件選択・一括復元・完全削除は対象外。

`pnpm storybook` でNormalを開き、写真を2枚選んで「ゴミ箱に移動」を押す。件数・復元案内、キャンセル時の選択維持を確認し、再度開いて実行する。通常一覧から消え、ゴミ箱で1枚ずつ復元できることを確認する。Albumで所属解除との違い、Favoritesでも利用できること、Trashで入口がないことを確認する。

Savingは二重送信・終了の防止、Errorは全件失敗と選択維持、Not Foundは再取得して選び直す案内、Unknownはサーバー保存後の応答喪失と同一対象の再送、Refresh Errorは保存完了後の再取得だけの再試行、Over Limitは101枚の送信不可を示す。PC 1440×1000・393×852・320×568とキーボードで確認する。

## 構成と後続実装

既存の写真行のdeletedだけを同一トランザクションで更新する。元画像・表示画像・メタデータ・お気に入り・所属の保持は既存のゴミ箱と同じ。DB移行・ライブラリ・認証変更は不要。写真行をID順にロックし、個別所属・一括追加・削除・復元と直列化する。最後にDBへ適用された状態が最終結果。API・ロックの実装と実DB検証は仕様承認・マージ後に行う。検証分担と境界・競合の検証計画はproduct.md第14節を参照。

通常AppとStoryでコンポーネントを共有するため、仕様PRでも通常アプリに新しい入口が表示される。新APIはStorybookのMSWだけで提供し、製品APIではまだ利用できない。既存機能の操作と選択バーへの影響を確認する。Issue #21・#22は基準mainで実装済みで、Issue #24のお気に入り廃止を必須依存にしない。

仕様承認対象は画面・API・製品ルールと上記のデータ保持／競合方針。対象コミットへのPO承認・仕様PRマージ後にready条件を再判定する。実機Safari・Windows・実Tailscaleは本番適用前にPOが確認する。
