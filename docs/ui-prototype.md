## レビュー方法

`npm ci` 後 `npm run storybook` を実行し、「アプリ / ひより / アプリを操作する」を開く。サイドバーを畳むかCanvasを全画面表示すると、アプリ全体を操作できる。

- フォトから写真を開き、前後に移動する。キーボードの左右キー・Escapeも利用できる。
- 詳細からお気に入り、ダウンロード、情報、削除確認を操作する。
- ゴミ箱で削除した写真を開き、復元する。
- 写真名、サンプルの場所、アルバム名で検索する。
- アルバムを作り、写真詳細の情報から所属アルバムを変更する。
- 「写真を追加」でJPEG/PNG/WebPを選ぶ。成功した写真は一覧と詳細へ反映される。
- 写真なし、読み込み失敗、読み込み中はそれぞれ専用Storyから開始する。

表示・操作状態の正は `src/App.stories.tsx`。これは本番機能の受け入れ完了を意味しない。

## 試作の構成

React、TypeScript、Vite、Tailwind CSS、shadcn/uiの構成に沿ったローカル所有のButton/Dialog（Radix UI、CVA、clsx、tailwind-merge）を使用。依存の具体バージョンは `package-lock.json` に固定する。

アプリ用の単一Storyに実際のApp全体をマウントし、React RouterのMemoryRouterで遷移する。単独起動とStorybookはAppを共用し、同じMSWハンドラーがAPIリクエストを処理する。

試作APIの契約案は `api/openapi.yaml`（OpenAPI 3.1.0、JSONはYAMLとして有効）。`npm run generate:api` で型、クライアント、MSWルートを生成する。生成物はコミット対象で、直接編集しない。`src/mocks/scenarios.ts` の手書きシナリオがメモリ内のサンプル値と更新を管理する。型は生成した契約に従い、入力の主要な型も検証する。完全なOpenAPI契約検証・CI・本番APIは今後の作業。

## 制限

- 保存はMSWのメモリ内のみ。再読み込み・Story切替で初期状態に戻る。2人の端末間の共有・永続保存は実装していない。
- アルバム作成は画面状態内、写真の所属変更はモックAPI内で保持する。
- 日時・場所・ユーザー表示は架空のサンプル。アップロード日時も固定値。本物のEXIF抽出や人物認識はない。
- 認証、Tailscale連携、権限制御、本番バックエンドを実装していない。公開デプロイ・マージは行っていない。
- 削除は試作上のゴミ箱移動のみで、完全削除や保持期限を規定しない。
- サンプル写真の出典は `public/photos/SOURCES.md`。本番で使用する素材の権利確認は別途必要。
- ストレージ使用量など、実データに基づかない数値は表示しない。

## 検証

`npm run build` で型検査と単独アプリのビルド、`npm run build-storybook` でStorybookの静的ビルド、`npm run test:e2e` でStorybook内の主要操作をPlaywrightで検証する。テスト内容は `tests/app.spec.ts` を参照。

Playwrightは既定でこの管理環境の `/usr/bin/chromium` を使う。他環境では `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を設定するか、Playwrightブラウザーをインストールして設定の実行パス指定を省略する。

自動アクセシビリティ監査、実認証・永続性・2端末の結合テスト、本番APIの契約テスト、CIは未実施・未導入。
